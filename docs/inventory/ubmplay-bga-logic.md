# uBMplay 1.5.2 的 BGA 裁切

`#BGAxx` 把一张 `#BMP` 的矩形贴到客户区上的一个点。256 是直接贴图和视频用来居中的名义列宽，不是 `#BGA` 的裁切框。这不是源码恢复。字段合同在 [UX-early.md](../../out/validation/ubmplay-parity-20261020/ida/bga/UX-early.md)，指令地址在 [UX-report.md](../../out/validation/ubmplay-parity-20261020/ida/bga/UX-report.md)。

样本仍是 imagebase `0x400000`、MD5 `44e3d8aa24e2eb19d1e426fde4086d03` 的那份 exe。

## 一条定义

命令末两位是 36 进制下标，范围 `0..1295`，含 `00`。参数用空格切开，只取前七个词：

$$
\text{src},\; x_1,\; y_1,\; x_2,\; y_2,\; dx,\; dy
$$

源号是 16 位。大于 1295 改成 0，0 和负数保留。四个坐标是 `CLng`，`dx` 和 `dy` 是 `CInt`。若 $x_1 > x_2$ 或 $y_1 > y_2$，交换那一对，使较小的在前。缺词当 0。同一下标以后出现的定义覆盖前一条。

1296 个槽的源号起初是 -1。-1 表示这个号没有 `#BGA`，通道值直接当作 `#BMP` 号。

## 贴到客户区

左缘：

- `AutoSeparate` 为假，或 `#PLAYER == 3`：331。名义列覆盖到窗口右缘 587。
- 其余：173。名义列覆盖到 429。

客户区上限是宽 587、高 256。

有定义时，目标是

$$
x = \operatorname{int16}(\text{左缘} + dx),\quad y = \operatorname{int16}(dy)
$$

矩形保持 $\{x_1, y_1, x_2, y_2\}$。16 位加法溢出则跳过这一次绘制，不绕回。这里没有把结果交进 256 列。

没有定义时，目标 x 是左缘加上 $128 - \lfloor width / 2 \rfloor$，y 是 0。源矩形底边在高度小于 256 时用原高度，否则用 256。宽度不封顶。一张比 256 更宽的图会伸进名义列左右两侧。

静止图按文件自己的宽高拷进表面，不在装载时缩放到 256。拷贝运算是 `SRCCOPY`。

落在 587×256 里面、名义列外面的像素是说明书里的溢出演出。调用点没有把它们删掉。窗口外还有没有 GDI 裁剪，这次没有打开。

## 层

| 通道 | 当前号 | 何时画 |
| --- | --- | --- |
| 04 | base | 模式含 bit0，且号不是 0 |
| 07 | layer | 模式含 bit1，且号不是 0 |
| 06 | poor | 模式为 4，或两名玩家记录的 `+4 >= 3` |

Poor 这一帧画完就结束，base 和 layer 不再画。Poor 的号即使是 0 也查 0 号槽。

模式 0 不画，并且读谱时若当时就是 0，`#BMP` 整段不装载。1 只画 base，2 只画 layer，3 先 base 再 layer，4 只画 poor。默认是 3。`+4 >= 3` 在模式 0 也会把该帧换成 poor。这个 `+4` 还没有对上判定档的名字。

号 0 只对 base 和 layer 表示“不画”。`#BGA` 槽里的源号 0 表示 `#BMP00`，合法。`#BGA00` 会写入 0 号槽。源号大于 1295 被改成 0 之后，也按 `#BMP00` 裁。

写过的 `#BGA` 槽优先于同号 `#BMP` 的直接贴图。

## 透明

没有 alpha。`Transparent` 是 0 到 255 的字节，缺省按 0 读入。0 不改像素，只有本来就是 `0,0,0` 的点是纯黑。大于 0 时，若图像对象返回的那个值大于 8，也不改。否则三个颜色字节都小于等于阈值的像素写成 `0,0,0`。拷贝之后还有一次参数为 0 的虚表调用。画面上的 `ini:Transparent :` 只在这个字节非 0 时出现，不参与改像素。

## 视频

打开后保存 `movieGetWidth` 和 `movieGetHeight`。绘制时 y 再加 $(256 - height) / 2$，目标宽高用保存的整帧，不把 `#BGA` 的四个坐标当成目标宽高。那四个坐标会另送到另一个槽，那个槽的函数体还没打开。

exe 里能看见的 256 是这个居中，不是长边缩放。说明书写长边缩放到 256，`movie.dll` 里的对应运算这次没有证完。

暂停把播放标志写成 -1 并调用 `moviePause`。恢复清掉标志并 `moviePlay`。拖动位置时把 Currency 换成双精度再除以 1000，交给 `movieSetPosition`；暂停标志非 0 时不再 `moviePlay`。这个 Currency 和谱面时钟的衔接还没接上。

## 和命令表字面不同的几点

命令表里 uBMplay 1.5.0+ 允许 `#BGA00` 和 `#BMP00`，`0 0 1 1` 算 1 像素，负的 `dx/dy` 伸出左上时不切。槽初值 -1、源号 0 走裁切、调用点不裁 256 列，和这三句相符。1 像素那一句还差纹理绘制函数里的减法。

同一页写 BM98de 会把负的 $x_1, y_1$ 改成 0。这份 exe 只交换逆序的一对，不把负数改成 0。

同一页的 x 4031、y 8190 没有出现在解析或绘制调用的立即数里。坐标类型就是上面的 `CLng` 和 `CInt`。

分隔符只有空格。`#@BGA`、`#SWBGA` 进不了 `#BGA` 比较。通道立即数是 4、7、6，没有 10。


## 视频入口更正（父代理与sol独立核对）

早期UX把`0x42A780`的垂直居中公式套到了实际BGA路径，这个映射不成立。原始指令见`ida/parent-movie-*.json`及兼容审计的`movie-draw-entry-and-scale.json`。

私有方法表的public15/16，经`0x4041E1/0x4041EE`跳到`0x42AC60/0x42ACE0`，读取对象`+0x40/+0x44`宽高，对应虚表`+0x58/+0x5C`。这两个已知getter锚定槽位：实际DrawBGA的`+0x44`为public10，跳`0x42A580`；`0x42A780`为另一个`+0x48`入口。

`0x416CD7`使用`+0x44`并传入y=0。`0x42A580`用传入y直接建立目标矩形，先`0x416F90`裁切，再调用`+0x88`换算源矩形。它不额外加`(256-H)/2`。垂直居中仅在另一个`+0x48`整帧入口中，因此当前G2实现对视频统一垂直居中的行为需要修正。

打开视频时`0x429E2E/31`保存初始宽高后，`0x429E34`调用`+0x84`。私有`0x42AD60`将初始宽高存入`+0x4C/+0x50`，按长边与256的比例存Float32到`+0x48`，再分别除该比例并通过`__vbaFpI4`存回显示宽高。说明书“最长边256”得到对应的EXE内部运算证据，不是movie.dll直接缩放；VariantDiv参数方向仍由审计结合运行库合同核对。

`+0x88`的`0x42AE80`把传入源矩形四角分别乘比例`+0x48`，再以`__vbaFpI4`换算到原视频像素。G2/G3尚未实现这套视频缩放/源矩形；静止图1:1和视频最大边256应分开处理，不能把这项差异写成已验。
