# uBMplay 1.5.2 谱面解析、seek 与选项

对象是 `out/reference/ubmplay-1.5.2/ubmplay/uBMplay.exe`（MD5 `44e3d8aa24e2eb19d1e426fde4086d03`，镜像基址 `0x400000`）。IDA 里有 429 个函数。没有对应源码。过程名来自函数里的宽字符串，和错误日志参数在同一处。

证据和分级在 [`out/validation/ubmplay-parity-20261020/ida/UQ-report.md`](../../out/validation/ubmplay-parity-20261020/ida/UQ-report.md)。这里只写已经能复刻的行为和还不能写进测试的缺口。等级：已确认、推断、未覆盖。

## 读入边界

`LoadBMSData`（`0x41B840`）在 `0x41BB45` 把一行交给 `LoadBMSLine`（`0x41C340`）。该函数也在三处递归调用自己。

一行的处理顺序：

1. `Left(line, 1)` 不是 `"#"` 就退出。
2. 只把第一个空格换成冒号，再按冒号拆开。第一段做 `UCase`，作为命令 token。参数是原行从 `Len(token)+2` 开始的剩余部分。
3. 先处理 `#RANDOM` / `#RONDAM` / `#IF` / `#ENDIF` / `#END`。
4. 随机栈顶的活动字 `+4` 为 0 时，这一行丢弃。
5. 否则调用 `LoadBMSHeader`（`0x41CDB0`）。返回 AX 非 0 表示头字段已经吃掉这一行。返回 0 才调用 `LoadBMSObjects`（`0x41DEC0`）。

header 成功时把返回槽写成 `-1`，结尾 `mov ax, word ptr [ebp-20]`。入口把该槽清 0。

通道行没有空格也能拆开，因为拆分符就是冒号。`#00111:0A0B` 的 token 是 `#00111`，参数是 `0A0B`。

## 随机栈

数组 `dword_42E070`，元素 8 字节。当前帧下标是 `UBound`。

| 偏移 | 含义 | 等级 |
| --- | --- | --- |
| `+0` | Long，本次掷出的值 | 已确认 |
| `+4` | Word，活动标志，`-1` 或 `0` | 已确认 |
| `+6` | Word，本帧是否已经见过 `#IF` | 已确认写入；名字是推断 |

`0x421500` 把上界加 1。`0x421640` 把上界减 1，小于 0 则保持 0。元素大小立即数是 `8`。新帧三个字段的初值来自带 bad-sp 的伪码，标推断：`+0=0`，`+6=0`，`+4` 复制上一帧。

`#RANDOM` 和精确 token `#RONDAM` 走同一块。若当前 `+6` 非 0，先压入新帧。然后若新栈顶 `+4` 非 0：

\[
\text{value} = \mathrm{CLng}(\mathrm{Int}(\mathrm{Rnd}\times n)+1)
\]

`n` 是 `Val(参数)`。`+1.0` 的常量在 `0x401A70`。结果写入 `+0`。`Rnd` 的值域在 `MSVBVM60`，exe 没有再夹范围。`+4` 为 0 时不掷骰。

`#IF` 比较的是 `CDbl(当前 +0)` 和 `Val(参数)`。相等则 `+4=-1`，否则 `0`。仅当 `UBound>0` 且这次相等时，再把 `+4` 改成上一帧的 `+4`。因此外层不活动时，内层数值即使相等也会变成不活动。然后 `+6=-1`，不再解析数据。

`#ENDIF`：当前 `+6` 非 0 时不弹栈，先把 `+4` 设为 `-1`，若 `UBound>0` 再抄上一帧。当前 `+6` 为 0 时调用 `0x421640`。两种情况最后都把当时栈顶的 `+6` 清 0。

`#END` 且 `UCase(参数)` 为 `IF` 时，改写成字面量 `#ENDIF` 再递归。参数不是 `IF` 则整行忽略。

没有空格时：`Left(token,7)` 为 `#RANDOM` 则递归 `"#RANDOM " & Mid(原行, 8)`。`Left(token,3)` 为 `#IF` 则递归 `"#IF " & Mid(原行, 4)`。`#RONDAM` 没有无空格形式。`#RANDOMPATTERN` 的前 7 个字符也是 `#RANDOM`；这条会不会在读谱时被先截走，还没看调用方，标未覆盖。

`#WAVxx`、`#BMPxx`、`#BGAxx`、`#BPMxx`、`#STOPxx` 用 `Right(token, 2)` 做索引，`Left(token, Len-2)` 做命令。索引解码见下一节。

`#HARLEMSHAKE` 会调用 `LoadBMSObject`。生成了什么通道文本还没还原。

## 36 进制

`0x421F30` 对每个字符累加 `digit * 36^(剩余长度)`。底数是 double `36.0`（立即数 `0x40420000`）。

`0x422070`：

- `A`–`Z`（先 `UCase`）：`Asc - 55`，所以 `A=10`，`Z=35`。
- 其他字符：`(Asc - 48) mod 36`。`'0'`–`'9'` 得到 0–9。小于 `'0'` 时余数可以为负。

`ZZ = 1295`。索引表上界 1296 与此一致。`00` 得到 0。

## 通道行

`LoadBMSObjects` 要求 token 长度至少 6。

- 小节号：`Mid(token, 2, 3)`，`Val` 成 16 位整数。十进制，不是 36 进制。
- 通道号：`Mid(token, 5, 2)`，再做 36 进制。
- `0x421780` 返回 0 时整行丢弃。
- 返回值等于 3 时，不按两位切分，整段参数交给 `0x41E1E0`。映射表里只有 BMS 通道 `02` 得到 3。
- 其他通道：参数长度除以 2，每两位调用一次 `LoadBMSObject`。

`0x41E1E0`：`Val(参数) > 0` 时，把 `Val * 192.0` 转成 Currency，写入 `dword_42E014[小节]`。元素 24 字节，只写开头 8 字节。这是小节长度。`Val<=0` 不写。

## 对象

`LoadBMSObject`（`0x41E2B0`）`retn 18h`，6 个参数。数组 `dword_42E010`，`ReDim` 元素大小 `0x28`。下标步长 `index * 40`。计数在 `dword_42E06C`。

两位文本先做 36 进制。结果 `<= 0` 时不增加计数，下一条会盖掉刚写的槽。内部号 27（BMS `03`）改为把 `"&H"` 和这两位文本做 `StrCat`，再 `Val` 成 Long。拼接方向还没钉死，不能把“一定是十六进制 BPM”写成已确认。其他通道把 36 进制结果直接放进 `+0x1C`。

已看到的字段：

| 偏移 | 内容 | 等级 |
| --- | --- | --- |
| `+0` | Word `0xFFFF` | 已确认 |
| `+2` | 内部通道 | 已确认 |
| `+4` | 调用方传入的标志；后面 LN 会改 | 已确认有写入 |
| `+8` | 小节号 | 已确认 |
| `+0x0C` | `CyI4` 的 8 字节 | 已确认有写入；公式未覆盖 |
| `+0x1C` | 音序号或 BPM 值 | 已确认 |
| `+0x20` | 玩家标记 1 或 2 | 已确认，仅内部号 9–26 |
| `+0x24` | 链接下标 | 已确认 LN 路径会写；初值来源未覆盖 |

小节号若大于 `word_42E46E`，就更新这个全局。渲染、按键和 seek 都会读它。把它当成最大小节号是推断，比较和写入已确认。

## `#LNOBJ`

创建对象时不读 `word_42E498`。`LoadBMSSort`（`0x41E6D0`）在该字为 0 时跳过整段。否则扫描对象，`+0x1C` 等于这个序号才继续。

还要同时满足：

- 标志不是 `0x1000`，也不是 `0x10000`（`0x4222F0`）。
- 内部通道在 9 到 26（`0x422340`）。

然后从当前下标往前找通道字相同、且 `+0x24 == -1` 的对象。找到时把那个对象的 `+4` 写成 `0x4000`，并在双方的 `+0x24` 写入对方下标。找不到时，当前对象的 `+4` 会写成 `0x2000` 或 `0x4002`。往前找和“同一通道”来自 `0x41F3AB` 的减 1 以及 `0x41F403` 的通道比较，链接语义标推断。`#LNTYPE` 字面量不存在；长音只观察到 `#LNOBJ` 和 `5x`/`6x` 的 `0x4000` 标志。

## seek

`SeekBMS`（`0x4201E0`）的参数是有符号 Word。函数自己把 EBX 清 0。小于 0 改成 0，大于 `word_42E46E` 改成这个最大值。然后调用 `SoundPause`（`0x4232C0`）和 `0x41B5E0`，并按小节长度数组重写若干 Currency 全局。后面的播放头公式未覆盖。

`KeyMain`（`0x4173A0`）用 `dword_42E4D0` 的 Word 数组表示当前按键，下标是虚拟键码，上界 `0x100`。非 0 就触发：

| 偏移 | 虚拟键 | 传给 seek 的小节 |
| --- | --- | --- |
| `+0x26*2` | Up | 当前小节 `dword_42E10C - 1` |
| `+0x28*2` | Down | `+ 1` |
| `+0x21*2` | PageUp | `- 4` |
| `+0x22*2` | PageDown | `+ 4` |
| `+0x24*2` | Home | `0` |
| `+0x23*2` | End | `word_42E46E` |

这是当前状态非 0 就调用，没有在这段里再看边沿。按住是否每帧都 seek，取决于 `KeyMain` 的调用频率，标推断。

进入 seek 时，播放状态 `dword_42E5B4` 若是 0 或 `0x0C`，会改成 `0x0A`。状态为 0 且标题字符串 `0x42E478` 长度为 0 时，跳到 `0x420E21`，不继续。

## 暂停、空格、速度键

`0x418930`：状态已经是 `0x0A` 时改成 `0x0B`，调用另一个 `SoundPause`（`0x4230E0`），再对 BGA 数组每个对象调用虚表 `+0x38`。

`0x418A00`：状态是 `0x0B` 时改回 `0x0A`。

`KeyMain` 在 `0x417AF8` 和 `0x417B04` 调用这两个函数。调用点附近比较了主键 `0` 和数字键盘 `0` 的槽，但 eax 怎么变成 `0x0A` / `0x0B` 还没逐条对上，按键到暂停的对应标推断。

空格是虚拟键 `0x20`，槽偏移 `0x40`。该槽非 0 时读一个计时对象。计数值 `>= 500`、闩 `word_42E0C2` 为 0、并且 `0x42E460` 的字符串非空时，把状态设为 `1`，并把闩设为 `-1`。500 和 readme 里的 0.5 秒数值相同；计时单位在 exe 里没有字面量，标推断。状态 `1` 和 `LoadBMS`（`0x41A900`）的衔接在 `CountMain`，还没展开。

主键 `1`/`2` 与数字键盘 `1`/`2` 同时按下时，调整 float `0x42E548`：大于 `1.0` 则减 `0.25`，小于 `1.0` 则加 `0.25`。单独按 `1` 或 `2`，以及 `3`/`4` 的 RealHS，比较了对应槽，步进还没还原。

## 明确未覆盖

- `CountPlay`（`0x418D70`）里的时间推进。它由 `CountMain` 调用，和渲染计时是另一条线。
- `LoadBMSSort` 里除 `#LNOBJ` 循环以外的排序。
- 对象 `+0x0C` 的小节内位置公式。
- RealHS、BGA/效果/皮肤/音量的按键步进。
- ini 值的类型和默认值。
- `#WAV` / `#BMP` / `#BGA` 定义如何放进对象数组。
- 随机栈最初的 `ReDim` 和元素初值。
- 429 个函数的其余部分。不要把本页当成完整复刻。
