# uBMplay 1.5.2 原版逻辑

这是对官方 `uBMplay.exe` 的只读静态结论，用来给预览的时间、按键和画面做对照。不是源码恢复，也不是 429 个函数都已经翻译成行为。Hex-Rays 对这份 VB6 native 二进制有 bad sp，尺寸、除法和分支以反汇编或原始字节为准。证据和置信度在 [UR-report.md](../../out/validation/ubmplay-parity-20261020/ida/UR-report.md)，视觉侧先看的摘要在 [UR-early.md](../../out/validation/ubmplay-parity-20261020/ida/UR-early.md)。精灵源矩形、目标位置和 SkinType 车道表在 [UR2-early.md](../../out/validation/ubmplay-parity-20261020/ida/UR2-early.md)，证据在 [UR2-report.md](../../out/validation/ubmplay-parity-20261020/ida/UR2-report.md)。DrawText 居中、判定比较顺序和 `dword_42E550` 的写入在 [UR3-report.md](../../out/validation/ubmplay-parity-20261020/ida/UR3-report.md)。

样本：`out/reference/ubmplay-1.5.2/ubmplay/uBMplay.exe`，imagebase `0x400000`，MD5 `44e3d8aa24e2eb19d1e426fde4086d03`。入口 `0x4028c0` 把 `0x402b64` 的 VB 头交给 `ThunRTMain`。SubMain 在头偏移 `+0x2C`，值是 `0x40b850`。语言 DLL 名是 `VB6JP.DLL`，LCID `0x411`。

同目录的 `image.dll`、`movie.dll`、`sound.dll` 只做了导出表阅读，没有放进当前 IDA 数据库。

## 启动和资源

`StartUp` 用虚表 `+0x1C` 打开 `image\font.png`。皮肤循环下标 0..4，文件名是 `image\skin_` + 两位十六进制 + `.png`。包内 PNG 只有 `skin_00` 到 `skin_03`，另有 `font.png`。

图集 IHDR：`skin_00` 331×256，`skin_01` 137×221，`skin_02` 160×244，`skin_03` 578×228，`font.png` 258×35。

`LoadConfig` 读取 `ubm.ini`。出现过的键：`Font`、`RecentFile`、`AlwaysOnTop`、`VSYNC`、`SinglePlay`、`ForceReload`、`Effect`、`SkinType`、`Info`、`Volume`、`Transparent`、`AutoSeparate`、`MineDefault`、`Sound`。另有路径 `sound\engine.ogg`。

exe 里有 ASCII：`image.dll`、`imageOpen`、`imageGreyToBlack`、`movie.dll`、`movieOpen`、`sound.dll`、`soundOpen`。这三个 DLL 的导出还包括宽高、DC、播放位置和 `soundRead`。`imageGreyToBlack` 的阈值算法在 DLL 内，这次没有反汇编。

## 时间和滚速

`flt_42E540 = 1000 / word_42E53E`。除数来自 `0x40e410` 的一次虚表 `+0x50` 调用，调用点在 `0x40cf95`。1000.0 是 `dbl_4013A0`。把这个整数当成刷新率，和说明书的“定时器 FPS 等于刷新率”相符，调用目标本身没有名字。

`CountPlay` 在 `0x418e65` 计算 `240000 / (dword_42E480 * 192)`。192 是 `flt_401958`，240000 是 `dbl_401950`。UT 已把这个商确认为每 tick 的毫秒：被除的时间差是 `timeGetTime` 的帧间隔再乘 `dword_42E54C * 0.01`。`qword_42E0E8` 加上所得的 tick。`0x419a82` 会用谱面事件改写 `dword_42E480`。240000 等于 4×60000。若这个 dword 是 BPM，则 192 tick 正是一小节、48 tick 是一拍。写入点旁边仍然没有 `#BPM` 字符串。小节长度本身是 `Val * 192`，seek 把累计和抄进 `42E0E8`，所以 tick 单位不依赖那条 BPM 推断。细节在 [UT-report.md](../../out/validation/ubmplay-parity-20261020/ida/UT-report.md)。

`0x41977a` 把 `flt_42E548` 乘进 `CountPlay` 的量。这就是画面滚速。

`flt_42E548` 的调整在 `KeyMain`：

- 与 1.0 比较。大于 1 减 0.25，小于 1 加 0.25。这是两个键一起按时向 1 靠拢。
- 下限与 0.25 比较。
- 另一条路径先加减 0.25，乘 4，`__vbaFPInt`，再乘 0.25，结果仍在 0.25 网格上。

键 `1`..`4`、Up、Down、PageUp、PageDown 都登记到 `0x417ef0`，参数是整数 50 和浮点 1.3。按住加速走这一组参数。Seek 对 `dword_42E10C` 做 ±1 或 ±4 后调用 `SeekBMS`。说明书把它们定成 1 小节和 4 小节。

`dword_42E54C` 是另一个整数，默认比较点是 100，步长 5，低于 100 则加 5，高于 100 则减 5，减方向在小于等于 25 时停止。增加方向还要小于 `dword_42E550`。改完调用 `ChangeFrequency`。判定窗把这个数乘 0.01 当比例。说明书写 RealHS 步进是 x0.25；这份反汇编里的整数步进是 5（若 100 表示 1.00，则是 0.05）。两套说法不要合成一个公式。浮点 0.25 只属于 `flt_42E548`。

更正（UR3）：`dword_42E550` 的写入已经单独追完，算术和仍缺的虚表槽名在 [UR3-report.md](../../out/validation/ubmplay-parity-20261020/ida/UR3-report.md)。`LoadConfig` 的 `0x40f74f` 把这个上限写成 200。有谱面对象时，`LoadBMSData` 会按 `clsSoundBuffer` 数组的查询结果重写它，并立刻调用 `ChangeFrequency`。

`CheckFPS` 用 `0.001` 做除法，结果在 `flt_42E5B8`，并且先和 500 比较。`DrawMain` 有 `FPS  :`、`Timer`、`VSYNC` 叠字。

## 按键状态

选项不是在 `KeyMain` 里直接 `cmp` 字符 `'5'`。它读一张键槽 word 表，槽位成对出现（大约相差 `0x60`）。下面的全局量是按下对应槽时改写的。

| 全局 | 运算 | 结果 |
| --- | --- | --- |
| `flt_42E548` | ±0.25，双键向 1.0 | 画面 HiSpeed |
| `dword_42E54C` | ±5，地板 25，天花板 100，另一侧天花板是 `dword_42E550` | 改完调 `ChangeFrequency`，并缩放判定窗 |
| `dword_42E554` | 加 1，大于 4 写成 0 | 0..4 共 5 态。`DrawBGAs` 与 4 比较 |
| `dword_42E558` | `x = 2x+1`，大于 7 写成 0 | 序列 0、1、3、7。bit0=1，bit1=2，bit2=4 |
| `dword_42E560` | 按位取反，再调窗体虚表 `+0x58` | 布尔。位置对应说明书的置顶 |
| `dword_42E55C` | 加 1，超过栈上的上限写成 0，然后调用 `0x418010` | 重建坐标。低两位选择切片增量 |
| `dword_42E564` | `0→1→6→7→0` | 四态。按 bit 可解释成无 / 播放 / 曲+选项 / 全部 |

`DrawBomb` 测试 `dword_42E558` 的 bit1。因此 0 没有该层，1 只有最低位，3 含爆炸，7 再含高一位。叠字 `NONE`、`LIGHT`、`MIDDLE`、`HEAVY` 与这四态数量相同。

BGA 叠字是 `OFF`、`BASE ONLY`、`LAYER ONLY`、`ALWAYS MISS`。计数器有 5 个值，标签有 4 个可见字符串。说明书还有“通常显示”。哪个值对应哪句字，还没有从 switch 连上。

搓盘叠字是 `L/R`、`R/R`、`R/L`、`L/L`。`dword_42E55C` 的模数在栈上，四态是推断。

信息叠字还有 `Play`、`Song`、`Play/Song`、`Option`、`Play/Option`、`Song/Option`、`ALL`。键循环只经过 0、1、6、7。

声音叠字：`BGM ONLY`、`KEY ONLY`、`MINE ONLY`、`KEY&BGM`、`KEY&BGM&MINE`。F1 的状态变量这次没有单独钉死。

`0x417bc8` 把局部量和 500 比较。说明书的空格 0.5 秒重载与这个常数同量级，路径还没独占到空格槽。

## 画面几何

客户区在 `0x417285` 一带被钳到宽 587、高 256。超过才改，等于上限。

原文：`DrawText` 用 `587 - 文字长度` 再除以 2 做水平居中。某个参数小于 0 时写成 122。

更正（UR3）：居中路径按 ASCII 公式 `(587 - 8*LenBstr)/2` 计算。`0x414aec` 调用 `__vbaLenBstr`，`0x414af2` 把返回值放进 `ecx`，`0x414af4` 执行 `imul ecx, 8`，`0x414afd` 装入 `0x24B`（587），`0x414b02` 相减，`0x414b0a` 到 `0x414b0f` 用 `cdq`、`sub eax, edx`、`sar edi, 1` 做向零的带符号除以 2。原版这一步的单位是 8 像素。`0x414ae4` 的 `jge` 会跳过这段计算。小于 0 写成 `0x7A`（122）仍在 `0x414b16`，作用在另一个参数上。字节在 `ida-audit-snippets.json`。

`dword_42E470 == 3` 时，`0x418010` 写入 0、173、158、331、331。否则写入 173 和 587，另外两个种子是 15 和 429。429 = 173 + 256。331 与 `skin_00` 的宽度相同。

`0x4155f0` 的 `push` 里，219 是车道亮条的高，18、15、32 是白键、蓝键、搓盘的宽，17 和 36 是白键和搓盘在 skin_01 上的源 x。目标 y 是 0，所以亮条底边在 219。`DrawMain` 同时使用 224 和 173。变量名在二进制里不存在。

`0x418010` 后半按 `dword_42E55C` 的 bit0、bit1 从种子累加 `word_42E19C`。增量仍是 +1、+20、+34、+53、+125，再加 +35、+70、+105。算完的数是音符精灵的目标左边缘，完整的四态表在后面的「精灵和车道」。`#PLAYER != 3` 时 2P 会超过 256，因为 2P 种子是 429，仍在 587 宽的客户区里。图片上的分隔线 0/33/52/68/87/103/122/138/157 是 SkinType 0、`#PLAYER == 3` 时精灵右边缘，不是这张字表的原样。

`dword_42E55C` 的写入点旁边是 ini 键 `SkinType`（`0x40f7d0` 起，`0x40f803` 存入）。它的低两位决定下面的车道表，不是另一套尚未命名的 scratch 变量。键处理把它加 1，和栈上的上限比较，超过则写成 0，再调用 `0x418010`。

`DrawObj` 的 `imul 6` 和 `DrawBomb` 的 64、96 已经落成下面的源矩形，不再只是候选步长。

`DrawMain` 调用顺序：`DrawBGAs`、`0x4155f0`、`DrawNotes`（内部 `DrawObj`）、`0x4158f0`、`0x415b20`、`DrawBomb`、`0x416280`、`PAUSE`、`DrawText`。

## 自动判定

原文：函数 `0x419e10` 取绝对值后的时间差，按从窄到宽的四个阈值归类。`dword_42E48C` 选择系数：

更正（UR3）：归类按下面四次比较的汇编顺序进行。阈值保持这个顺序，不按数值重新排序。`dword_42E48C` 选择系数：

| `dword_42E48C` | 窄窗系数 | 宽窗系数 |
| --- | --- | --- |
| 0 | 1.0 | 0.8 |
| 1 | 1.6 | 1.0 |
| 2 | 2.5 | 1.0 |
| 3 或更大 | 4.0 | 1.0 |

四个阈值是 `窄系数 * dword_42E54C * 0.01 * 10`、`* 20`，以及 `宽系数 * dword_42E54C * 0.01 * 50`、`* 60`。

`dword_42E54C == 100` 且 rank 0 时，四个阈值是 10、20、40、48。rank 1 时是 16、32、50、60。rank 2 时是 25、50、50、60。rank 3 时是 40、80、50、60。

更正（UR3）：上一行的四个数是比较顺序，不是排好序的窗宽。rank 3 在 `dword_42E54C == 100` 时依次比较 40、80、50、60。`0x419fcd`、`0x41a001`、`0x41a037`、`0x41a060` 都是 `fcomp`，后面是 `test ah, 1` / `jnz`，当前阈值小于绝对时间差才进入下一档。绝对差小于 80 时已经落在前两档；能走到 50 和 60 时，绝对差已经大于 80，这两档不可达。rank 大于 3 走同一套系数。实现保持汇编顺序。

比较是“阈值 < 绝对值就看下一档”。落点写入的代码依次是 `ebx`、1、2、3，最后一档是 4。前两档还会以参数 `0x2000` 调用 `0x419ce0`。`ebx` 在这段窗口之前的值没有单独摘出。五档和叠字 PERFECT/GREAT/GOOD/BAD/POOR 数量相同，名字对应是推断。

`0x419ce0` 用 `参数 - 9` 做下标，下标必须小于 18，然后写每车道 16 字节的记录。18 路够放双人 16 列加余量。它和 BMS 通道号的换算还没逐通道对上。

原文：把 `dword_42E48C` 当成 `#RANK`（0 最严）是推断：头解析读 `#RANK`，而且 0 的窗最窄。

更正（UR3）：`#RANK` 写入 `dword_42E48C` 已由 UQ 直接确认。`UQ-early.md` 的比较在 `0x41D044`，`Val` 后 `FpI4` 写入该全局；`UQ-report.md` 的写入站点是 `0x41D061`。0 的窄窗系数仍是 1.0 / 0.8。判定档名，以及进入这四次比较之前 `ebx` 的具体值，仍然没有别的编译覆盖。

## 读谱

`LoadBMSHeader` 引用 `#PATH_WAV`、`#PLAYER`、`#GENRE`、`#GENLE`、`#TITLE`、`#ARTIST`、`#BPM`、`#PLAYLEVEL`、`#STAGEFILE`、`#RANK`、`#TOTAL`、`#VOLWAV`、`#LNOBJ`、`#OCT/FP`、`#BMP`、`#BGA`、`#STOP`，以及第二次出现的 `#BPM`。`LoadBMSLine` 引用 `#RANDOM`、`#RONDAM`、`#ENDIF`、`#END`、`#IF`。

exe 里没有 ASCII 或 UTF-16 的 `LNTYPE`。`#LNOBJ` 有。说明书写两种 `#LNTYPE` 都支持；这份二进制不能用字符串证明它在找这个词。长音的通道状态机和 `#STOP` 的时值换算都还没还原。

`ReadCmdLine` 能看到扩展名 `.BMS`、`.BME`、`.BML`、`.PMS`、`.TMP` 和形如 `N999` 的片段。`-N`、`-P`、`-S`、`-Q`、`-SP`、`-FR` 的分支没有逐个对上。

## 精灵和车道

表面数组 `dword_42E42C[i]` 在 `StartUp` 里按下标 0..4 装入 `skin_00`..`skin_04`。`font.png` 在另一个对象 `dword_42E438`。包内没有 `skin_04.png`。

`0x416f30` 的原始字节把五个参数写成矩形：`left, top, right=left+width, bottom=top+height`。绘制虚表槽的参数，按调用前的 `push` 顺序是：

| 槽 | 参数 |
| --- | --- |
| `+0x44`、`+0x48` | 对象、目标 x、目标 y、源矩形指针。矩形的宽高就是画上屏幕的宽高 |
| `+0x4C` | 对象、目标矩形、源矩形。用于拉高的长音体和放大中的判定字 |

两个单点槽的差别没有过程名。下面“源”都是图集像素，“目标”都是屏幕或合成表面上的位置。

### 目标 x：SkinType

`#PLAYER` 写入 `dword_42E470`（`0x41ceb9`）。启动时先写成 1。`== 3` 时 1P 种子是 0、2P 种子是 173，两套右边界都是 331。否则 1P 种子是 15、2P 种子是 429，右边界是 173 和 587。

`0x418010` 用 SkinType 的 bit0 摆 1P、bit1 摆 2P。bit 为 0：搓盘在该侧块的左边（种子 +1），白键/蓝键从种子 +34、+53 起，再每列 +35。bit 为 1：键从种子 +1、+20 起，搓盘在种子 +125。因此 0、1、2、3 的左右是 L/R、R/R、L/L、R/L。这和说明书的四句顺序一致；叠字跳转本身这次没有再连。

### skin_01 音符

`DrawObj` 在 SkinType 不等于 4 时用表面 1。内部通道是对象 `+2`。源矩形左/右按内部号减 9 查跳转表 `0x41555c`：

| 形状 | BMS 通道 | 源 x | 宽 |

| 蓝键 | 12、14、18、22、24、28 | 88 | 15 |
| 搓盘 | 16、26 | 104 | 32 |

源高都是 5。顶边：

| 对象 `+4` | 顶边 | 帧 |
| --- | --- | --- |
| `0x2000` 普通 | `1 + (帧 & 7) * 6` | 帧 = `Int(tick / 4.8)`，8 帧。tick 是 `qword_42E0E8` 的 Currency 数值，48 tick/拍，不是每秒 48 |
| `0x4000` 长音头 | `97 + (帧 & 3) * 6` | 帧 = 同一只 tick 的整数部分除以 24，4 帧。同一次调用再画 `0x4001` |
| `0x4001` 长音体 | `73 + (帧 & 3) * 6` | 源高仍是 5。目标高是两条 Currency 之差乘 `flt_42E548` 后的整数，目标顶 = 音符 y 减这个高 |

### 车道亮条和键位光束

`0x4155f0` 在 `word_42E1C0[内部号-9] != 0` 时，从 skin_01 拉一条到判定线附近的竖条，目标 `(车道 x, 0)`：

| 形状 | 源 x | 源 y | 宽 | 高 |
| --- | --- | --- | --- | --- |
| 蓝键 | 1 | 1 | 15 | 219 |
| 白键 | 17 | 1 | 18 | 219 |
| 搓盘 | 36 | 1 | 32 | 219 |

这个字由 `0x419ce0` 写成 `0xFFFF`，由 `0x41b667` 写成 0。绘制函数里没有键盘扫描。它是车道亮起，不能单独当成物理键按下。

光束在 `0x4158f0`。还要 `dword_42E558` 的 bit2。表面同样是 SkinType 不为 4 时的 skin_01。源矩形和键帽上的目标：

| 形状 | 源 x,y,w,h | 目标 |
| --- | --- | --- |
| 白键 | 69, 139, 13, 20 | `(车道 x + 插入, 233)` |
| 蓝键 | 83, 139, 12, 20 | `(车道 x + 插入, 227)` |
| 搓盘 | 96, 139, 28, 28 | `(车道 x + 2, 226)` |

1P 插入：搓盘在左时白键 +3、蓝键 +2；搓盘在右时白键 +2、蓝键 +1。2P 只有 21、22 号跟着 2P 自己的搓盘方向，其余 2P 键复制了 1P 的插入量。寿命是毫秒：`dword_42E100 - dword_42E1E4[车道] > 50` 时把 `word_42E1C0` 清 0。`0x416280` 不是光束，是判定字和连击。

### skin_02 判定字和连击

`0x416280` 测试 `dword_42E558` 的 bit0，表面下标 2。源高 14，宽 81 的字和宽 15 的数字：

| 内容 | 源 |
| --- | --- |
| 五帧循环的 GREAT | x=9，y=`106 + (时钟/50 mod 5) * 15`，w=81，h=14。对象 `+4 == 0` 时走这里 |
| 按等级选的一行 | x=9，y=`181 + (槽内值 - 1) * 15`，w=81，h=14。槽内值来自 `dword_42E190` 那条记录的 `+4` |
| 数字 0..9 | x=`9 + 数字 * 15`，w=15，h=14。记录值为 0 时 y=`1 + (时钟/50 mod 5) * 15` |

时钟是 `dword_42E100`。等级值 1..4 的 y 为 181、196、211、226，都落在 skin_02 的 244 像素高度里。第 5 档会用到 y=241，底边超出图高，这次没有证明那一档会进来。图上能看到多行 GREAT 以及 GOOD、BAD、POOR；哪一个整数对应哪一个词，绘制函数里没有字符串。

稳定后的目标 y 是 `word_42E22C - 59`。这条 word 在普通布局是 220，所以 y=161。目标 x：玩家标记低位为 0 用 `word_42E398`，为 1 用 `word_42E39A`。没有连击数字时再加 35。有数字时以 119 为中心，减去字宽的一半和 `(位数 * 15 + 88) / 2`。数字从判定字右侧排开，步长 15，并先减 7。

开始后的 90 个时钟单位内改走 `+0x4C`，高度约 `7 * s + 14`，y 约减去 `3.5 * s`。`s` 来自 `0x4109e0(int(256/360 * (年龄 + 90)))`。`0x4109e0` 的表没有展开。满 90 后改回 `+0x44` 的原始尺寸。

### skin_03 爆炸

`DrawBomb` 测试 bit1。槽在 `dword_42E174 + (内部号-9) * 16`。`+0` 非 0 才画。年龄 = `dword_42E100 - 槽+4`。帧号 = `(年龄 / 20) mod 6`，共 6 帧。`+0Ch == 0` 且年龄 `>= 120` 时把 `+0` 清 0。

`dword_42E100` 每圈由 `CountMain` 从对象 `dword_42E0F8` 的虚表 `+0x1C` 读入。UT 追到这个槽就是 `clsTimer` 对 `winmm.timeGetTime` 的差，单位是毫秒。爆炸因此是 20 毫秒一帧、120 毫秒清除。暂停状态 `0x0B` 不刷新这只表。STOP 不进入 `0x0B`，爆炸继续走。

表面下标 3。源 x = `1 + 帧 * 边长`：

| 谁写入 | 槽 | 源 y | 边长 |
| --- | --- | --- | --- |
| `0x419630`，参数 `0x4000` | `+0Ch` 为真 | 163 | 64 |
| `0x419924`，参数 `0x4002` | `+8 == 0` 且 `+0Ch` 为假 | 66 | 96 |
| `0x41a01d`，第二参数立即数 1 | `+8 == 1` | 1 | 64 |
| `0x419fe4` | `+8` 等于当时的 ebx | 由 ebx 决定 | 64 或 96 |

`0x419630` 和 `0x419924` 在判定/计数路径里，分别带着长音标志 `0x4000` 和 `0x4002`。两个 `0x2000` 调用是前两档判定。ebx 那一档的初值这次没有摘出，所以不能把 96 像素行独占给 PERFECT。

比较发生在减 9 之前的循环下标上。下标 9..15 和 18..24 用车道 x + 8，其余用 +16。会玩到的搓盘是内部号 17 和 26（BMS 16 和 26），它们落在其余里。目标中心 y = `word_42E22C + 4`（普通布局是 224）。左上角再减去半个边长。

## 播放时钟

`qword_42E0E8` 是谱面 tick，不是秒。通道 `02` 的长度是 `Val * 192`，排序把前面各小节的长度和写到下一小节记录的 `+8`，seek 把 `+8` 抄进这只 Currency。192 tick 为一小节，48 tick 为一拍。

播放时 `deltaTick = 毫秒差 * (RealHS整数 / 100) * dword_42E480 * 192 / 240000`。RealHS 默认 100 时系数为 1。HiSpeed 不乘这个增量。普通音符和地雷的帧是全局 `Int(tick / 4.8)`，长音是全局 `I4(tick) / 24`。同一时刻同类音符共用一帧。

`dword_42E100` 是另一只 `clsTimer`。类名在 `0x404834`，ObjectInfo 是 `0x402BF8`。虚表 `+1Ch` 返回 `timeGetTime() - 对象基准`，单位毫秒。`0x4050B8` 只是错误检查用的接口槽，不是类。`StartUp` 调用 `timeBeginPeriod(1)`。exe 不导入 `GetTickCount`。

暂停状态 `0x0B` 不采样 tick，也不刷新 `42E100`。恢复时把暂停毫秒加回音符表和效果表的基准。STOP 剩余大于 0 时只冻 tick；效果毫秒继续走。`#STOP` 的 Long 按 1:1 变成 tick。

光束超过 50 毫秒熄灭。爆炸 20 毫秒一帧、120 毫秒清除。判定字在 1080 毫秒时清掉；槽值为 0 时的五帧是全局 `毫秒/50`，不是这一次的年龄。

给实现用的式子在 [UT-early.md](../../out/validation/ubmplay-parity-20261020/ida/UT-early.md)。地址在 [UT-report.md](../../out/validation/ubmplay-parity-20261020/ida/UT-report.md)。
