# 开发工作流

本文记录当前已进入实现阶段的开发约定。设计、任务边界和验收方式继续作为约束；实现工作已经启动，但不表示全部功能、兼容性或验收已经完成。

## 明确产品范围

- Preview 使用应用内置的非模态原生窗口。
- Preview 可以播放尚未保存的文档内容。
- Preview 支持可选停靠。
- 不要求配置外部播放器。
- `woslicer` 已加入范围。它的准确版本、功能、来源和许可证仍需先行研究并记录，当前不宣称已经实现。

## 分工和模型

父代理负责设计、任务拆解、独立的详细差异审查、测试，以及集成批准。父代理不编写实现代码，也不直接编写实现修复。

所有实现代码和修复都由子代理完成，并明确指定模型：

- 有界、简单的任务使用 `gpt-5.6-luna`。
- 涉及复杂格式、音频、并发或集成的任务使用 `gpt-5.6-terra`。

## 拆解和执行任务

每个子代理开始前，任务说明必须写清以下内容：

1. 任务契约：输入、输出、接口和行为约束。
2. 独立写入范围：允许修改的文件列表或目录边界。
3. 测试预期：需要新增或运行的检查，以及通过条件。
4. 本批次预计变更的文件列表。

不同子代理的写入范围必须互不重叠。子代理只修改分配范围内的文件，并在完成后报告实际变更的文件和测试结果。

## 审查和集成

每完成一批代码，父代理都要独立检查完整差异，重点确认接口契约、边界行为、错误处理、测试覆盖和范围控制。发现问题后，父代理把具体修复要求发回原子代理；修复仍由该子代理完成。

修复完成后，父代理重新审查差异并运行任务说明中的测试。只有测试通过、差异符合契约且没有越过写入范围，父代理才批准集成。任何新增代码批次都重复这套流程。

官方归档：[woslicer II](https://cerebralmuddystream.nekokan.dyndns.info/soft/woslicerII.zip)（SHA-256 `5079a6739295f02167d2a12796da3df1632d3d96123aabd4f72881f7bb8f4c65`）和 [woslicer III](https://cerebralmuddystream.nekokan.dyndns.info/soft/woslicerIII.zip)（SHA-256 `8319d792a792f9051a31cdf0ea3c9bdcbc2b1bbf18209560329970273592a22c`）。帮助里的 24 条能力和哈希写在 `docs/inventory/woslicer-windows.md`。

集成方式：原生重做，不移植 exe。现在只有命令清单和空壳窗口，还没有切片，客户区还没从 Windows 原版量过。不宣称已经接入或像素通过。
