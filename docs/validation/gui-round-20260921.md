# 电脑操作界面测试与窗口播放复测（2026-09-21）

本轮用电脑操作工具驱动真实窗口，做了两件事：在 `IBMSNative` 上走一遍编辑器日常操作，在 `BmsONE` 的 GPU 播放器上做窗口播放复测。测试用的谱面和截图都写在 `out/validation/gui-test-20260921/`，没有改动仓库里的产品代码。

结论：编辑器的主要界面操作都能走通；GPU 播放器的播头在这轮窗口播放里保持 1 倍速，没有复现上一轮的画面与音频半速脱节。屏幕实际帧率仍只是应用自报的读数，人耳听到的延迟无法用截图验证，这两项仍不能算验收。另外发现一处新问题：同一个播放器窗口里停止后再按播放，音符不触发，连击数一直是 0。

## 测试用的谱面

`out/validation/gui-test-20260921/test-chart.bms` 是这轮手写的夹具，覆盖短音、NT 长音、BPM 变化、STOP、BGA 和两格 WAV，音频用 `tone.wav`（与谱面同目录）。

## IBMSNative 界面测试

打开夹具后，界面显示与文件内容对得上：

- 标题栏是 `test-chart.bms - μBMSC Editor 3.2.1`，没有星号，表示干净。
- 右侧栏读到 `TITLE=GUI Test Chart`、`ARTIST=Codex`、`GENRE=Test`、`BPM=120`、`PLAYLEVEL=5`、`RANK=3`。
- WAV 列表 01、02 都显示 `tone.wav`；谱面上能看见 A1–A8 的短音、A1 的 NT 长音和 BGA 上的事件。
- 菜单栏这一轮是中文（之前选过语言包）。文件、编辑、视图菜单的项目与 `current-status.md` 里列的一致，未接通的项目仍是禁用状态。

写入和保存链路：

- 切到写入工具后在编辑区点写，标题立刻带星号，说明文档变脏。
- 另存为 `junk-01.bms` 后对比原文件：写出内容加了 `HEADER FIELD` / `MAIN DATA FIELD` 横幅，表头按 `PLAYER`、`GENRE`、`TITLE` 的顺序重排，小节行按最大公约数压缩（`#00111:01000000` 写成 `#00111:01`），并写回了一条新记录。
- 另一份 `probe-h.bms` 里能读出 8 条短音记录（通道 11、12、13、15、16、18、19 和 06），和界面上统计窗口的数字一致。
- 撤销 / 重做可用：一次撤销后仍是脏，重做回到保存点后星号消失；连续撤销 12 次后重新变脏。

对话框：

- 统计信息窗口（`482 × 254` 客户区）显示 A1–A8 短音 7 个、总值 8 个，与文件里的记录数一致。
- 查找 / 删除 / 替换窗口（`474 × 422`）显示了音符范围、小节范围、标签范围、数值范围、列选择和操作按钮，布局与 `diagFind.Designer.vb` 一致。
- 编辑 → 偏好设置打开 BmsONE 的四页设置（General / Edit / Preview / BMS Import）。
- 在 SCROLL、BPM、STOP 列点写会弹出输入框（`Please enter a SCROLL value.` 等），取消后不写入。这几句提示仍是英文。

内置预览：

- 按 F5 打开 `预览` 浮动窗，窗内有「从开头播放」「从当前位置播放」「停止」三个按钮。音频是否真的出声无法用截图判断。

## BmsONE GPU 播放器窗口播放复测

打开 `out/validation/full-chain-round4-20260921/gui/from-bmsone.bmson`，主窗口正常显示标题、`beat-7k`、分辨率 240、`tone.wav` 声道和波形，没有出现上一轮记录过的卡死。

### 播头速度

第一段用「GPU Player from Beginning」启动，截图状态栏读出的播放时钟如下：

| 采样 | 墙钟间隔（秒） | 画面时钟 | 增量 |
| --- | --- | --- | --- |
| 1 | — | 00:13.128 | — |
| 2 | 11.52 | 00:24.645 | 11.517 |
| 3 | 11.52 | 00:36.083 | 11.438 |
| 4 | 11.30 | 00:47.438 | 11.355 |

34.33 秒墙钟里画面时钟走了 34.310 秒，比值 0.9994。

第二段改用播放器状态文本轮询：00:00.825 → 00:05.924 → 00:11.024，两段间隔分别是 5.092 秒和 5.089 秒，对应 1.001 和 1.002 倍。

按修好之后的实现，播头最多只比已生成的音频早约 50 ms。两段测量里播头都保持 1 倍速、没有持续落后，说明上一轮「画面走到 53 秒、音频才生成到 27 秒」的脱节在这轮未复现。

### 其他读数

- 播放器自报帧率 113–121 FPS，稳定在 120 附近。
- `BmsONE` 进程 CPU 占用采样三次为 42.9%、6.9%、4.7%，第一枪含窗口合成，之后稳定在 5% 上下。
- 暂停可用：按下暂停后画面时钟在 4.5 秒内没有变化；停止后状态回到 `IDLE`、时钟归零。

### 新发现：停止后重新播放不触发音符

复现步骤：

1. 在主窗口点「GPU Player from Beginning」，播放开始后连击数（COMBO）为 2，与谱面上两颗音符对得上。
2. 在同一个播放器窗口点「Stop」，状态回到 `IDLE`、时钟归零、连击归零。
3. 在同一个窗口点「Play / Pause」。

结果：时钟从 0 正常按 1 倍速走（1.786 秒、4.936 秒），连击数始终是 0，两次复现结果相同。关掉窗口、再从主窗口「GPU Player from Beginning」重新打开，连击数又回到 2。

也就是说，时钟和音频调度还在跑，但这一次播放里的音符事件没有触发。最像的解释是停止时释放了声道缓存、重新播放时没有重新准备，需要看代码确认。

## 这轮没能验证的部分

- 屏幕实际刷新率：播放器自报的 113–121 FPS 是应用自己的计数，不等于显示器实际呈现的帧率。
- 人耳听到的延迟：电脑操作工具只能取窗口截图和可访问性文本，无法采集系统音频输出，所以「扬声器出声时刻」没有测量。
- 鼠标点击坐标：自动化工具传给应用的点击坐标与窗口截图坐标不一致（同样的窗口，截图宽 1082，实际可点范围明显更窄），所以编辑区的点写位置只能靠保存后的文件反推，不能逐个像素核对。这是工具的限制，不是产品结论。
