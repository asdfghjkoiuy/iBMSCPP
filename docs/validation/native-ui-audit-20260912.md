## 已确认的问题

1. **侧栏分组上下颠倒。** 截图中 Header 和 Grid 标题在组内容下方，Expand 在上方；WAV 列表也出现在组标题上方。`OptionsSidebar.swift:1423` 的 `OptionsSectionView` 使用普通 NSView，却按从上到下的 y 坐标布局，未覆盖 `isFlipped`。原版 Designer 使用顶部停靠。这不是字体差几个像素，而是布局方向错误。
2. **启动空文档不完整。** 本次首次启动可重复操作链是：字段不可用 → Command+N → 字段和网格恢复。需要让启动生成与 New 相同的有效文档状态。
3. **移动音符边界检查失败。** `core/src/bms_document.cpp:1897` 在源和目标坐标相同时直接返回，早于检查源音符是否存在。自动测试要求不存在的源被拒绝。本次没有修复，也不将其夸大为已经发生的数据丢失。
4. **预览离目标差距较大。** `LegacyPreviewAudio.swift:334` 用主线程 `asyncAfter` 逐次触发声音；播放器使用 AVAudioPlayer。界面没有下落画面或 BGA。不能据此宣称达到低延迟、稳定同步或高负载播放要求。
5. **预览说明已经过时。** 窗口仍写系统不能解码 OGG 就静音，但当前代码已有 OGG 解码回退，相关自动测试通过。产品文案和实现不一致。
6. **bmhelper 初始布局需要复查。** 截图中大块空白占据主窗，分隔条的可访问性位置为 0，上方源 MIDI 区没有正常展开；右侧长按钮文字被截断。本次未加载工程，不能推断加载后的钢琴卷表现。

## 技术栈与软件设计建议

保留现有 C++20、Swift 6、AppKit、Objective-C++ 桥接和 Metal。当前工程已采用这些技术，编辑器也已有真正的 Metal 顶点绘制，同时用 AppKit 绘制文字等内容。

- C++ 核心保留 BMS、BMSON 两种文档模型，各自负责格式语义、未知字段、时间与资源。统一的是编辑命令接口和界面，不强行把 BMSON 转为 BMS 后编辑。
- Swift + AppKit 管理窗口、菜单、文件对话框和输入。固定客户区布局与自绘控件负责原版外观；系统深色控件、圆角、字体和滚动条不能自动算像素等价。
- 预览应单独成模块：编辑器输出不可变播放快照；后台解码并缓存音频；C++ 调度与混音通过 Core Audio / Audio Unit 输出；以音频样本时钟驱动 Metal 轨道和视频帧。BGA 解码可放在 AVFoundation 模块。以上是建议，当前尚未实现成这套结构。
- bmhelper 作为 MIDI 与 division 服务，BmsONE 作为 BMSON 编辑和音频服务，切片算法共用一个工具界面。逐步减少依靠独立主窗和剪贴板串联的流程。
- 继续拆分大型控制器。当前 MainWindowController 为 5308 行，ChartRenderer 为 3668 行，DocumentSession 为 1566 行。已有模块文件，但职责仍集中，后续修改容易互相影响。

beatoraja 官方项目使用 Java / libGDX，并明确支持 macOS。macOS 并非绝对无法使用外置播放器；本项目仍应按用户要求提供内置原生预览。此次只核对了官方项目说明，没有完成其播放线程、音频后端和资源缓存的深入源码审计，不能宣称已经借鉴并实现其播放方式。来源：https://github.com/exch-bms2/beatoraja
