# 第三轮全链路复测（2026-09-21）

第二轮的四项问题在本轮对应测试中通过：切换 BUF 后播头没有倒退，真实音频输出探针没有测到时钟倒退，自然结束后保留结束位置，原生应用可以打开 BmsONE 的谱面并显示音符。

但全链路仍未通过。发现新的反向互通问题：原生应用保存 BMSON 后，BmsONE 打开这份文件会无响应，持续占用约一个 CPU 核心。另外，时钟探针通过不能代替实际画面帧率和音画同步验收。

本轮只做测试并记录结果，没有修改产品代码。

## 新问题：原生保存后，BmsONE 打开无响应

严重程度：阻断跨应用往返编辑。

复现步骤：

1. 将第一轮 BmsONE 保存的文件及音频复制到本轮 `gui` 目录。
2. 用原生应用打开 `gui/input.bmson`，修改标题并保存。
3. 用本轮重新构建的 BmsONE 打开保存后的文件。
4. 窗口无响应；测试进程持续约 99.7%～99.8% CPU，超过 4 分钟仍未返回。

保存后的 JSON 仍写 `version: "1.0.0"`，但根字段为 `bpmNotes`、`stopNotes`、`soundChannels`，初始速度为 `initBPM`，不再保留 snake_case 字段。原生解析器可以自读，BmsONE 则按版本选择另一套字段。

源码证据：`core/src/bmson.cpp` 的写出逻辑保留版本并使用 camelCase；`BmsONE/src/bmson/Bmson.cpp` 对 `1.0.0` 直接返回输入对象；`Bmson100.cpp` 定义的字段为 `sound_channels`、`init_bpm`。`DocumentInfo.cpp` 直接将缺失的初始 BPM 字段转为数值，缺失时得到 0。

线程采样确认主线程停留在以下调用链：

`FileOpen → OpenBmson → ReplaceDocument → MiniMapView::ReconstructRmsCache → MasterCache::GetData`

波形缩略图重建会用 BPM 作除数，再将结果转换成采样位置。字段缺失导致 BPM 为 0，与此次异常计算路径一致；这里是结合源码与采样作出的原因判断，没有用调试器逐项读取运行时局部变量。

建议后续同时处理两处：原生写出的版本与字段格式保持一致；BmsONE 在进入时间及波形计算前拒绝或修正无效 BPM，避免输入异常拖死主线程。本轮没有实施这两项修改。

已保存复现文件与 5 秒线程采样，随后结束本轮启动的无响应进程（PID 67917），确认进程已退出。
