# WMV 支持独立审计（2026-10-21）

本报告是只读现状研究与实现验收清单。未改产品代码或测试，未启动前台 UI，未运行长测。实现完成后的具体 diff 结论另补。

## 当前证据

- `macos/Sources/IBMSNative/PreviewBGAView.swift` 的 `PreviewBGAFiles.videoExtensions` 已列 `wmv`，但 `PreviewBGAChannel.openVideo` 无条件创建 `AVPlayerItem(url:)`，没有 ASF/WMV 解码后端。列扩展名不能证明格式支持。
- 图像路径的 `PreviewBGAImageLoader` 对 overlay 做逐像素阈值黑键；现有 AVPlayerLayer 路径没有对应的视频黑键。新增帧后端应明确保留 base、overlay、POOR 三层区别。
- 已有 BGA clock 支持从事件拍到 Here 起点的媒体偏移并包含 STOP；已有 request/generation 保护异步图片和 AVPlayer seek；已有关闭模式不解析路径的契约。新增后端应保留这些语义。
- 本机 `/opt/homebrew/bin/ffmpeg` 8.1.1 的 decoder 列表包含 `wmv1`、`wmv2`、`wmv3`、`vc1`（以及 image 变种）。encoder 列表只有 `wmv1`、`wmv2`，因此 WMV3/VC-1 不能靠本机编码器临时生成来覆盖。
- 本机 ffmpeg 配置含 `--enable-gpl --enable-version3`。直接随 app 分发这套库应明确 GPLv3 边界，不能称为纯 LGPL 分发。
- `otool -L` 显示 libavcodec/libavformat/libswscale/libavutil 之外还有 Homebrew x264、x265、openssl、libvpx、dav1d、lame、opus、SvtAv1、libswresample 等依赖；只复制四个直接链接库不足以支持 app 搬移。

## 建议的最小可靠方案

在 `.wmv`/`.asf` 的受支持范围接入 native libav 视频帧解码桥。为每个活动层保留独立 decoder 状态，后台串行队列负责文件打开、demux、视频 decode 和 swscale；主线程只提交最新目标媒体时间与 epoch，并设置完成帧的 CALayer 内容。保留其他格式当前的 AVPlayer 路径可降低改动范围。WMV 解码可能使用 CPU 软件解码；存在 VideoToolbox 链接或 ffmpeg 的硬件功能配置不代表 WMV 已硬解。

推荐只保留当前帧、下一帧和一个最新请求，不预解整片。正常时顺序解码到目标附近，倒退或明显跳跃才执行 seek + decoder flush。目标时间来自已有 `PreviewBGAClock`；请求倍率仍由 0.25…4 的谱面时钟反映，不能再乘一次。hold 停止推进并保留已呈现帧；off/换谱则取消并释放。解码量和保存图像的尺寸、字节数都应有界。

异步转码再交给 AVPlayer 可以复用现有播放器，但完整转码会增加首次出画延迟、磁盘缓存容量与失效逻辑，还需取消子进程、临时文件原子发布及 overlay 黑键方案。它可以是明确有状态的 fallback，不能假装成即时原生支持，也不能在主线程阻塞等待 ffmpeg。对长片和快速事件切换，视频帧桥更直接。

## 容易遗漏的验收点

| 方面 | 必须核对的结果 |
| --- | --- |
| 真实格式 | 用 ffprobe 确认 ASF 容器和 `codec_name=wmv1/wmv2/wmv3/vc1`；将 MP4 改名 WMV 不算；缺少某类真实样本时明确证据缺口。 |
| stream 选择 | 只选择实际视频流。不得打开音频 decoder；即使源含 WMA/其他音轨也不出声、不建立音频播放节点。 |
| FFmpeg 协议 | 正确处理 send/receive 的 EAGAIN、EOF、延迟输出与末尾 drain，不能把任意失败或 packet budget 耗尽当成正常 EOF。 |
| 时间戳 | 使用 stream time_base、有效 best_effort_timestamp/PTS、start_time；考虑缺时间戳、不从 0 起始、B 帧、可变帧率，首帧不应被错误 offset 跳过。 |
| seek | seek 到关键帧后 flush，解码到目标对应帧；倒 seek、Here、STOP、连续事件复用同一 URL、超出末尾均需稳定。不能每 tick 重开或 seek。 |
| 调度 | worker 串行拥有 AVFormatContext/AVCodecContext；最新请求覆盖旧待办，不能按 60 Hz 无限排队；帧发布不能积压到主队列。 |
| 取消 | decode/open/seek/frame completion 全部用事件 request 与谱面 generation 或等价 epoch；off/换谱后旧帧不可回写，旧 completion 不可恢复播放；hold 后晚到帧的契约需明确。 |
| 生命周期 | queue 上资源不允许与主线程 close/free 并发；取消是及时检查的 token，不只是 Task.cancel；视图销毁能释放 worker 而不形成闭包环。 |
| 内存与尺寸 | 防止宽高乘积溢出、极大分辨率、负 stride；输出帧、scratch、lookahead 都有明确上限；多个层同时播放不能线性囤积整片。 |
| 像素 | 输出格式与 CGImage bitmapInfo 一致，opaque alpha=255；黑键后透明像素 RGB 也置零；swscale 正确处理颜色范围，不能引入残留绿/紫或 alpha 全零。 |
| 黑键 | 仅 overlay 按 RGB 各通道 <= threshold 透明；threshold 0 和 255 边界正确；base/POOR 在 threshold 255 仍保留原色与黑色。 |
| 布局 | 视频帧应沿用 video geometry（长边归 256、顶对齐、crop 转原像素），不能误走静态图的 directImage 规则；保持 source crop、stage clipping、缩放与原来一致。 |
| 运输状态 | 暂停不重开、不继续 seek，末尾保留帧；0.25/1.05/1.95/2/4 倍率持续跟随；恢复播放不从零重开。 |
| 关闭态 | 关闭模式不查路径、不打开文件、不创建 decoder；正常模式不解码 POOR，切 POOR 时才建立相应资源。 |
| 错误 | 损坏 ASF、无视频流、缺 decoder、I/O 失败应成为可见失败状态；不在每个 tick 重试，不永久保持 loading。 |
| 搬移 | 从任意 cwd 运行搬移后的 bundle，所有非系统动态依赖递归位于 app，install_name/rpath 不指向 `/opt/homebrew`、`/usr/local` 或开发构建目录。 |
| 分发 | 核实架构和 macOS 最低版本兼容；复制及 install_name_tool 修改后做必要签名；保留依赖许可证/对应源码信息。 |

## 搬移验证的证据强度

仅复制 app 到 `/tmp` 然后在同一台有 Homebrew 的机器上运行，不能证明依赖完整。至少递归检查 app 主程序和每个 dylib 的 `otool -L`，确认除系统库外都解析到 bundle；再从搬移 bundle 运行不使用开发路径的 headless probe。若无法临时隔离 Homebrew 或在干净机器验证，应在结论中明确此限制，不能宣称已在无 Homebrew 环境验证。

## 当前审计结论

当前只证明 libav 可提供所需 codec 家族及现有 AVPlayer 路径的缺口，尚未证明产品支持任何真实 WMV 样本。需等待实现 diff 与短时 headless 证据，之后才能对功能、性能或 app 搬移作通过结论。

## WMVF 生命周期/调度中途复核

当前修复分支已引入 atomic accepted/revision、inflight 上限8、单帧槽，并将 Swift close 改为先摘下 raw 再通知 stop；正常 close 不再 join 主线程。正常 open失败会 publish FAILED 并等待 stop，调用方 close 后才回收，未发现该路径 UAF。以下两项仍为 P1：

- worker_main 的 catch(...) 后无条件 retire_control/delete Control。run_worker 内分配等异常会让 worker 在调用方仍持有 raw 时自行删除，后续 poll/close/command UAF；甚至可能在 open 的 thread 构造赋值尚未完成时删除 Control。异常应发布失败并等 owner stop，不能直接回收可见句柄。
- 每个连续前进 tick 改变 media_seconds 都 revision++，慢于 tick 的 decode/convert 被 superseded 后 force_seek=true，下一轮重新 seek 再次取消，可能永远无首帧。建议连续前进只合并最新目标，hard revision 用于 seek/backward/hold/generation/close；至少增加持续高频递增目标、慢于提交速率时有限时间内呈现帧且 seek 数有界的验证。

资源上限确实封顶为8，但达到上限 open 返回nil，上层立即成为永久 unplayable，无重试。此可用性问题记P2；现测试20次open/close只检查峰值和最终drain，并未断言每次open成功，不能证明快速换谱不会触发。当前 FFmpeg strict inventory 因隐式H.263视频依赖正在调整，最终仍需核实目标 decoder 和音频decoder数量0。此节是中途源码检查，等待最终hash复核。

构建可重复性补充（P2）：脚本 stamp 只包含版本；arch、min-version、编译器和组件配置改变时可能复用旧 prefix。建议把这些输入连同脚本哈希写入 stamp，且早退前确认四个 archive 均存在。当前 CMake 把四个库列为 OUTPUT，但脚本早退只检查 libavcodec.a 与头文件，删除其他 archive 后可能永远无法重建。
